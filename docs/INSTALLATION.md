# 安装说明

> [!WARNING]
> 当前版本（U-Boot `v0.1.0-pre.6` / BootBridge `v0.2.0-pre.3`）正在由测试人员上机测试，尚未取得整机验收结论。改写启动程序有变砖风险。

## 已装过本项目 U-Boot：从旧版升级

已装 pre.3、pre.4 或 pre.5 的设备，直接在救援页「U-Boot 更新」上传本版 `appsbl.mbn` 即可，见 [pre.6 说明](../releases/uboot-v0.1.0-pre.6.md#从-pre3pre4-或-pre5-升级)。HW-D 的 ECC8 机器在旧版上「U-Boot 更新」会失败，要先在「网页终端」加载本版 RAM 救援版，再写入。BootBridge v0.2.0-pre.3 安装的是 pre.5，装好后同样按这个步骤升级。用 BootBridge v0.2.0-pre.2 装上 pre.4 的设备也按这个步骤升级。

比 pre.3 更旧的版本：以前的救援页「固件更新」会留下 ECC 隐患，请升级后再刷一次固件。升级方法是在旧救援页的「网页终端」加载 RAM 救援版，再在新救援页写入 U-Boot（两份 APPSBL 一起写），完整步骤见 [pre.3 说明](../releases/uboot-v0.1.0-pre.3.md#从旧版升级)。不要用旧救援页的「U-Boot 更新」直接上传：它只写一份 APPSBL，HW-D 和部分 NAND 型号还会拒绝。

## 原厂设备：使用 BootBridge

首次安装请使用 [BootBridge](../tools/bootbridge/README.md)（网页版 <https://flyfish-go.github.io/H3C-NX30-Uboot/> 或 Windows 版）。流程是：

1. 选机型，获取工具指定的官方固件，并先用原厂升级页升级到这个版本；
2. 在工具里用这份官方固件生成桥接包；
3. 在原厂升级页上传桥接包；
4. 桥接程序启动后自动识别设备并检查安装条件，打开 `192.168.10.1` 维护页，先备份，再确认安装。

普通用户不需要选择 HW-A/B/C/D。工具识别不了或核对不通过时会停止，不要改用其他机型的文件。

**`appsbl.partition.bin` 和 MBN 不是原厂升级页接受的完整固件，不能直接上传。**

## 测试者

请先确认自己有串口或编程器等独立恢复手段，并保留样机的写前备份。按[测试记录模板](TEST-REPORT-TEMPLATE.md)提交去敏结果，本轮重点：

- `192.168.10.1` 恢复页能否打开（自动进入、按 Reset 进入两种方式）；
- 电脑是否自动获得 `192.168.10.x` 地址；
- 原厂 ENV 分区安装前后是否逐字节一致；
- 按住 Reset 实际需要的秒数。

HW-A/B/C/D 目录只用于追溯。相同商品名、主芯片、NAND ID 或 PCB 板印不足以决定安装资格。

## 进入恢复页

安装本版 U-Boot 后：

- 系统启动失败时会自动进入恢复页；
- 也可以断电后按住 Reset 再通电，保持几秒后松开；
- 或通过 UART 截停启动后输入 `httpd`。

电脑网卡设为自动获取 IP（会得到 `192.168.10.100`–`192.168.10.200` 之间的地址），浏览器打开 `192.168.10.1`。

## 恢复与备份

恢复依据是你自己的写前备份和精确样机流程。本项目不提供可供所有变体共用的恢复镜像，也不把 ECC 解码数据备份当作带 OOB/ECC 的编程器原始镜像。

pre.3 起，「闪存备份」导出整个系统分区时只包含本分区的好块，可以在救援页「固件更新」原样写回；分区里已经损坏的数据会在写回时被校验拦下，这种情况请改刷干净的固件。

备份包可能含设备身份、ENV、ART 和认证材料，应保存在本地私有位置，不要公开上传。
