# BootBridge v0.1.0-pre.6（测试版）

> [!CAUTION]
> **RT3000、RC3000、RW3000 / RW3010、RX3000 暂停使用（2026-10-24）。NX30 不受影响。**
>
> 已收到 RT3000 用户反馈：刷入本版桥接包后，安装向导报告 `candidate_contract_ambiguous` 而拒绝安装，「返回原厂系统」也因 ENV 检查不通过被拒绝，设备停在桥接系统里，不能当路由器使用。原因是上述机型的固件可能装在任意一类主板上，在 mp02.1 主板（HW-B、HW-D）上，HW-B 和 HW-D 两个候选会同时通过检查，安装向导无法区分；NX30 固件只对应 HW-D，所以不受影响。桥接系统没有其他退出方式，发布新版也无法替换已经刷入的桥接系统。
>
> - 刷机前无法判断自己的主板类别。修复版本发布前，请不要给上述机型生成或刷入桥接包（网页版、Windows 离线版都一样）。
> - 已经刷入的用户：设备启动区没有被写入。请不要再尝试其他刷机方式，在向导页下载诊断文件后，加 QQ 群 1131957442 或在 [GitHub Issues](https://github.com/FlyFish-go/H3C-NX30-Uboot/issues) 联系维护者。备份包里有设备敏感数据，请勿公开上传。

> [!WARNING]
> 本版正在由测试人员上机测试，尚未取得整机验收结论。改写启动程序有变砖风险；没有独立恢复手段和自己样机写前备份的用户，请等待测试结论。

## 本版变化

- **改进：安装完成页改为 RESET 救援入口说明。** 以前安装完成后，页面提示"上电 3 秒内通过串口中断，输入 httpd"进入维护网页，并注明"物理 RESET 入口未核验"。RESET 入口现已在实机上核验，页面改为：断电后按住 RESET 键再接通电源，红灯闪烁约 3 秒后转为绿灯常亮，此时松手即进入救援系统，用网线连接 LAN 口访问 192.168.10.1。四类硬件相同。
- 页面上的"维护网页"统一改称"救援系统"，避免和桥接系统混淆：桥接系统是通过原厂升级页刷入、用来安装 U-Boot 的临时系统；救援系统是 U-Boot 自带的网页（uBootKit）。两者都在 192.168.10.1。
- 安装完成页左下角不再显示"设备报告可能已修改"，改为"已写入新 U-Boot"。安装失败时的警示保持不变。
- 安装与检查逻辑没有改动。规则更新为 `H3C-BOOTBRIDGE-NAND-OEM-20261023-R8`，因为页面打包在桥接包内，四个机型的桥接包全部重新生成；同一份官方固件生成的桥接包与 pre.5 不同。
- 网页版与 Windows 离线版（x64 / x86）使用同一份规则，生成结果逐字节相同。

## 使用前请注意

- 注意区分两个页面：刷入桥接包后自动启动的是“BootBridge 设备安装向导”（桥接系统），U-Boot 要在这里安装；按住 RESET 开机进入的是 U-Boot 的救援系统（uBootKit），只有已装上本项目 U-Boot 的设备才有。
- 只接受上表机型对应的官方固件版本，按大小与 SHA-256 核对；不匹配时不会生成。
- 桥接包要通过原厂升级页上传；不要把 U-Boot 分区文件直接上传到原厂升级页。
- 任何文件都在你的电脑上处理，不会上传到本项目。
- 测试反馈请使用[测试记录模板](../docs/TEST-REPORT-TEMPLATE.md)，备份包请勿公开上传。

## 测试重点

1. 刷入桥接包后，能否打开"BootBridge 设备安装向导"页面并完成安装（HW-A、HW-B、HW-D 尤其需要）。
2. 安装完成页是否显示 RESET 救援入口说明；按说明操作能否进入救援系统。
3. 安装后串口启动日志中的 U-Boot 版本为 `3095c9527234`，电脑自动获得 `192.168.10.x` 地址。
4. 原厂 ENV 分区安装前后是否逐字节一致。

## 已知限制

- 覆盖安装（当前 U-Boot 不是原厂或已登记版本）后，BootBridge 的"返回原厂"不能恢复被覆盖的 U-Boot。
- 出厂 U-Boot 不在版本登记表里的设备，会走覆盖安装路径，同样不能用 BootBridge 返回原厂。
- NX30 / RX3000 需要在电脑上运行一次网页生成的命令来下载官方固件；命令输出目前只有中文。
- 网页版仅在 Chromium 内核浏览器实测，Firefox、Safari 尚未实测。
- 生产 U-Boot 自更新、ECC8、NOR 不在本版范围。
